Bounded synthetic trials cover the next engineering/productivity methods after `v0.8.0`. They are not a collection-wide reliability score. The baseline is `v0.8.0`, commit `e40f9e288362d534ee6eb373846e85241a637ad0`. Initial candidate packages match `915eb1eb6472aa57b313c05a1b26570562bfc027`; the workflow retry correction and its regression match `14571d01c074d9183b5d24dd593069769fcd2472`. Other skill bodies are unchanged between those candidates.

## Execution and assessment

Executors used Codex CLI 0.167.2 and native records report `gpt-6.1-sol`. All final candidate cases meet their applicable criteria. Four matched existing-skill cases show semantic/task-outcome parity, not demonstrated improvement. Candidate reads of the new conditional resources are observed; baseline packages lacked them, so baseline resource loading is not scored as an identical pass. New actions and retry behavior have candidate-only evidence.

## Correction and retained evidence

Independent source finding R1 identified an overbroad requirement to change input or approach before retrying any known error. This conflicted with an accepted bounded, idempotent retry of a transient failure. The entry and recovery resource now preserve permitted unchanged retries while distinguishing deterministic causes. The final-source retry case verifies that correction. The two original workflow cases use pre-R1 source; their exercised dependency/pending-operation paths are unchanged and do not prove the retry branch.

Candidate snapshots and installed owning packages were checked against source (281 package files; baseline 268). All fixtures remain unchanged. Runtime attempts delegated observations; their actual child command traces and returned assessments are retained privately, with verified hashes. Some shell wrapper forms were blocked by the read-only host before corrected successful commands; those failures remain retained. The retry attempt likewise retains its initially blocked shell form.

## Limits

Global host skill metadata is visible, so these are not clean-host activation trials. Raw native records may contain private configuration and stay private. Results do not establish live browser/site quality, durable workflow-engine recovery, provider effects, cancellation or resource cleanup, automatic routing, other models/clients or production reliability. Structural, installation and release checks are separate evidence.
