# Foundation readiness

- Purpose and the first supported behavior are clear.
- The selected runtime starts through documented commands; prerequisites and unavailable services are named.
- One representative path crosses the required real boundaries and has an observable result.
- Relevant lint/type/build/behavior checks run and their outputs are inspected; commands are not invented from package names.
- Configuration distinguishes safe examples from secret values. Generated output and local state have appropriate handling.
- Repository structure, dependencies, extension points, and contributor conventions fit the selected stack and project.
- Setup docs describe this project, not an untouched starter demo. Agent instructions point to authoritative context without copying the entire documentation tree.
- Delivery expectations and remaining work are explicit; local success does not imply production readiness.
