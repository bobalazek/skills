# Visual direction and craft

Use for a redesign, an unsettled visual direction or a substantial composition/type refinement. Keep the decisions in the existing design record or screen handoff; this guide does not require a separate brief file.

## Establish what changes

Inspect representative rendered pages, content, behavior and shared foundations. Compare them with the request and accepted decisions. Record conflicts instead of silently treating either an old document or the latest implementation as approval to replace the other.

| Starting point | Design decision |
| --- | --- |
| Local refinement | Name the defect or desired improvement and preserve surrounding identity, content and behavior. A spacing fix does not require new branding. |
| New surface within an existing product | Inherit established foundations; choose a composition for the new task. Extend a shared component only for an observed need. |
| Replacement design | Identify which visual choices may change and which product facts, functions, routes, accessibility behavior and explicit brand commitments must survive. A request to replace appearance does not authorize changing the offer. |
| New product or incomplete identity | Separate confirmed assets and constraints from open choices. Develop only the missing direction needed for the requested surfaces. |

For a website redesign, inventory the requested pages, shared navigation/footer, repeated templates and consequential states before selecting a representative page. Capture the current task paths and real content worth preserving. Track retained, replaced, merged or omitted regions with a reason; deleting a visible section may remove information or a route. Resolve an uncertain consequential removal before its dependent work, continuing independent pages.

Missing `DESIGN.md` does not erase a coherent design visible in the product. Equally, an explicit replacement request should not end as minor polish because old tokens happen to exist. Carry required approval from the actual project rules and current authorization, without adding a new approval step to settled choices.

## Turn context into a direction

Establish what the visitor needs to decide, do, read or explore on this surface. Note actual content volume, use frequency, supported devices/input, locale, accessibility needs and delivery constraints. Ask only about missing choices that change the result.

Turn those facts into inspectable decisions. A comparison task needs visible comparable attributes; a frequent editing task needs stable controls and prompt feedback; a reading page needs navigation and comfortable text; a portfolio may let the work occupy most of the opening view. These are starting hypotheses to check against the actual task, not universal page formulas.

Describe the proposed direction through its leading content, reading/task path, type roles, density, color roles, imagery and relevant interaction. Explain how those choices serve the surface. Adjectives such as “premium” cannot substitute for those decisions. Compare alternatives only when they resolve an open choice; change the structure or information emphasis, not just the accent color. Honor a supplied direction rather than inventing a concept contest.

For reference material, reuse inspected captures first. Select a bounded reference to answer a named question, such as handling dense filters or giving a project image enough prominence. Record source, inspected state, useful relationship and necessary adaptation. Keep estimated measurements and inferred behavior labeled. Do not blend unrelated motifs merely to appear distinctive, or copy assets, text and fonts without appropriate rights.

When a visual choice remains open, a supplied or generated image comp can be a useful proposal if the available tools and authority permit it. Keep relevant details readable and inspect the composition before implementation. Reconcile generated wording, assets and implied controls with actual content and behavior requirements; the image cannot establish facts or interactions. Compare the implemented surface with the accepted comp under comparable conditions, recording deliberate departures for content, accessibility or platform constraints. A settled design does not need another image-generation step.

## Work with actual content

Compose one representative complete surface before propagating a new direction through shared templates. Use its real content or labeled representative data, including a relevant long or empty case. Check the whole requested page, not only the opening viewport; an attractive hero does not establish a coherent page or site. Reuse accepted wireframes when structure is settled.

| Decision | Probe before spreading it |
| --- | --- |
| Hierarchy and grouping | At reduced detail, can the main action/content and major groups still be identified? Use proximity and emphasis to fix competing priorities before adding more borders, cards or decoration. |
| Typography | Identify heading, body, label, metadata and numeric roles actually needed. Check whether weight, size and spacing distinguish them with the real text. Inspect loaded fonts, fallback layout, long headings, clipped accents/descenders and zoom rather than choosing a scale by habit. |
| Density and rhythm | Match visible information to the task. Check comparison, scanning and repeated use; equal-sized containers should represent meaningfully equivalent content. Preserve useful repetition. |
| Color and imagery | Give color an identifiable emphasis, state or brand role. Check contrast against actual backgrounds and retain non-color cues. Inspect the loaded asset's actual subject and crop, including supported themes. Check reserved space and usable content when media loads slowly or fails. A plausible URL or successful fetch does not establish the intended image. |
| Adaptation | At supported narrow, intermediate and wide sizes, decide what wraps, reflows, scrolls or changes placement. Check that reading and focus order still follow the task, with long content and overlays present. |

Revise choices that fail these probes, then carry the accepted rules into the remaining requested surfaces. Recheck shared components where they meet different content and states. Avoid fixed aesthetic bans: a grid, system font or restrained palette can be correct when it serves the brief.

## Compare against the request

Return to the preservation/change inventory and every requested page/state. Compare valid baseline/result captures under comparable conditions. Explain material gains through observable differences, such as a visible primary action, retained destination or readable long title. An expert assessment does not demonstrate increased trust, comprehension or conversion.

Pass the candidate, original constraints, reference evidence, observed checks and open decisions to the independent review required by the entrypoint. Refresh affected evidence after corrections. Update authoritative design guidance from the final accepted result, rather than leaving discarded proposals as instructions for later work.
