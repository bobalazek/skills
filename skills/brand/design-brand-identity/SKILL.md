# Design brand identity

Produce the requested visual direction, identity guidelines or editable brand assets at the agreed fidelity. Preserve useful existing identity and approved source assets; a request for logo usage rules does not authorize a rebrand.

`define-brand-positioning` owns audience and promise decisions. `define-writing-voice` owns language conventions. `design-interface` owns screen composition and `build-design-system` owns shared UI tokens and component contracts. Brand work can finish without an interface implementation or a new component system.

## Establish the identity scope

Inspect the accepted positioning, current assets and guidelines, actual touchpoints and available source files. Establish whether the request preserves, refreshes or replaces the existing direction. Reuse accepted decisions; a small correction should not restart strategy.

Ask about consequential missing direction, retained marks or intended uses, and wait before dependent selection or production. Requested explorations and asset inspection can continue. Honor explicitly delegated choices instead of introducing blanket aesthetic approval. If no strategy exists, clarify the minimum audience, offer and intended associations needed for this scope; keep a provisional direction labeled rather than silently choosing new positioning.

## Develop the requested visual language

Derive direction from the audience, promise, distinctive existing assets and actual applications. Compare alternatives only when the direction is open. Explain choices through intended associations and practical constraints; color or shape does not guarantee a universal psychological response, recall or conversion lift.

Specify the relevant logo/mark variants, palette roles, type choices and fallbacks, imagery/icon conventions and usage examples. Add mascot invariants only when a recurring character is requested. Scale the asset set to the real touchpoints; not every brand needs a mascot, animated logo or extensive manual.

Check source and font licences against the intended use before adopting them. Preserve required attribution and identify unresolved rights. Inspiration is not permission to redistribute an asset. Keep generated concepts separate from accepted source assets; do not label a raster image an editable vector or claim trademark clearance from a visual review.

## Deliver the relevant assets and rules

For a reusable guideline or asset handoff, use [the identity handoff](references/identity-handoff.template.md), adapting the project's current format. For a scoped direction request, return the relevant exploration and constraints without manufacturing a production package.

Keep editable masters and requested exports distinguishable, with variant, background and intended use recorded. Give logo spacing/minimum-size rules a basis in actual samples rather than arbitrary universal numbers. Specify where typography and palette rules apply; a decorative brand color is not automatically suitable for interface text or controls.

When production assets are requested, inspect them in representative intended uses, sizes and backgrounds: readability, clipping, unintended distortion, font substitution, export transparency and relevant script coverage. Exercise the actual source/export path; a moodboard cannot prove working exports. Inspect contrast where text or functional graphics carry meaning, applying the consuming project's accessibility requirements. Record the contexts checked without claiming whole-product conformance from an identity review.

## Evaluate and return

Before acceptance of a durable identity or production asset handoff, obtain a separate fresh-context assessment of the raw brief, sources, candidate assets and use-context evidence. Retain the returned reviewer/session identity, evaluated revision, findings and coverage. Resolve supported defects and independently recheck affected uses; without an assessment, return an unreviewed draft. A small advisory answer can use direct checks unless it accepts a consequential decision or the user/project requires independent review. Do not substitute agent taste for audience-testing results or imply owner approval that was not given.

Return the requested artifact and its editable location, retained/new decisions, asset status, inspected uses, rights gaps and remaining work. Preserve private source material in its permitted location. Drafting assets does not authorize publishing them, replacing live branding or buying fonts and services.

## Continue when the next work is ready

Pass accepted identity rules and source assets to `build-design-system` for recurring UI foundations, `design-interface` for a requested screen or the relevant media workflow for an exported asset. Check availability or describe the plain action. If a rollout is requested, list affected touchpoints and replacement/verification needs before changing them. Continue authorized ready work; an identity-only request can end at the agreed direction or checked asset handoff.
