# Website audit report

Use the project's existing format first. Fill only applicable sections and keep evidence accessible to its intended reviewer.

## Scope and outcome

- Candidate/URL, available revision, observation date, business/audience and primary goal.
- Sampled routes, states, viewports/input methods and diagnostic conditions.
- Scope conclusion: what the evidence establishes and what remains unknown.
- Sources: direct observations, supplied captures/data, business facts and external benchmarks, distinguished by provenance.

## Findings

| ID / priority | Route, state and affected task | Observation and evidence | Consequence and confidence | Correction and verification |
| --- | --- | --- | --- | --- |
| Stable finding ID and project priority with rationale | Exact page/element and scenario | Quoted text, interaction, response, capture or measurement with conditions | Demonstrated impact; separate an uncertain cause or benefit hypothesis | Concrete next change or investigation and the result needed to close it |

Combine duplicate symptoms while preserving affected routes. Do not create findings merely to fill every lens. If a proposed change is preference or an experiment, label it accordingly.

## Coverage and limits

For each selected lens and material journey step, record observed, failed, not checked or inapplicable with a reason. Name inaccessible routes, blocked effects, unavailable tools, incomplete search/field data and untested platform/input variants. A supplied screenshot is supplied visual evidence, not a new browser run.

## Prioritized action plan

Link each action to finding IDs, expected user outcome, dependencies and the required recheck. Separate immediate repairs from investigation, experiments and larger planned changes. Give bounded effort estimates only when the implementation context supports them; state assumptions. Do not turn speculative conversion lift or modeled revenue into a forecast.

For a commercial scenario, identify the source and unit of each input, baseline window, assumptions and missing information. If those inputs are absent, return the missing-input list rather than invented arithmetic.
